# Changelog

Release notes for nexus-lite. Each GitHub Release uses its version section.

## v0.4.0

Loom loop mode (`LoomAdapter.serve()`) needs loom v0.4.0 or newer; the pinned default `LOOM_VERSION` is now 0.4.0.

### Changed
- **Run-dir layout: a valid sentinel is recorded as `skipped` (the sentinel path), as xrun does;** the old `skip` file is still read.
- **`nexus-lite job wait` no longer polls every 0.2 s:** it blocks on a kernel exit event (Linux `os.pidfd_open` + `select`, macOS `select.kqueue` NOTE_EXIT) after verifying the pid against the recorded start time and boot id; the fallback poll is 1 s (`poll_s` default 1.0).
- Bus names (target, consumer, session) must not start with `.` or `_` and are at most 128 bytes; `ALL` is stored upper-case.

### Fixed
- **PTY server lock no longer collides with launchers:** the server serializes on `<sock>.lite.lock` instead of `<sock>.lock` (a launcher may hold that one while it starts the server, which made the server fail with a lock timeout), checks that an existing socket's master is alive before replacing it, forwards input before the activity stamp, and throttles the stamp to once per 0.5 s.
- **Jobs (#48): `job start` no longer prepends lite's package dir to the job's `PYTHONPATH`** (the job sees the caller's environment plus `--env`). The launcher and supervisor run as `python -I -c ...` from the run dir with lite's parent appended to `sys.path`, so a stale backport in a site-packages dir (for example `dataclasses` 0.6) or a stray `json.py` in the job cwd can no longer shadow the stdlib. `start` returns only after the command was exec'd (new run file `launched`).
- **PTY spawn no longer crashes programs that are still starting up or whose resize handler is not reentrant:** `spawn()` set the initial geometry through an ATTACH + WINCH + DETACH connection, so the server signalled one extra SIGWINCH right before the capture worker attached; it now sends only the WINCH geometry.

### Added
- **`LoomAdapter.serve()` / `LoomLoop`: loom loop mode over the file bus (spec section 13).** Launches `loom serve --bus-dir DIR --name ID` and drives it with `task`, `inject`, `extract`, `resume` and `stop` messages; replies are matched by `meta.corr` and awaited on the wake-up path. Requires loom v0.4.0 or newer, i.e. a loom with `loop_mode` in `capabilities --json` (else `LoomLoopError`). `tests/test_loom_loop.py` uses a scripted fake serve; `tests/test_loom_loop_interop.py` is the Python<->Go contract test against a real binary (skipped without `LOOM_BIN`). Example: `examples/loom_loop_mode.py`.
- **`nexus-lite job` is a full detached-job engine (parity with xrun).** `job start --mem-max SIZE` (`64G`, `512M`, `N%`; none by default, `$NEXUS_LITE_MEM_MAX`): a systemd user scope with `MemoryMax=` when systemd really applies it, else a stdlib watchdog that kills the job's process group when its summed Pss/RSS passes the cap; the job dies alone, the run dir gets `memkill`, the log "memory limit exceeded", `meta.json` records `mem` (cap and enforcer), `status` shows the OOM, `check` adds `oom` / `mem_max_kb` and the `job` message verdict of a failed job is `OOM` (new `nexus_lite.jobs_mem`). A roots index (`nexus_lite.jobs_roots`; `~/.local/share/nexus/artifacts/.xrun-roots`, `$NEXUS_LITE_ROOTS_INDEX` / `$XRUN_ROOTS_INDEX`; one root per line, flock + rename, paths only): `job list --all`, `job roots [--prune]`, and `status|wait|check|tail|log|stop NAME` find a run started from another indexed root. `job log NAME` prints the log path. `job wait --xrun-exit-codes` (only OK exits 0; FAIL/GONE/SKIP 1; timeout 3). A job now sees `RUN_DIR` (its run dir unless one is inherited; `start --own-run-dir`). Run dirs written by xrun (ISO `started`/`ended`, `skipped`) are read correctly.
- **File bus: files are the bus source of truth, `lite.db` is lite's local, rebuildable index (#46, spec `docs/specs/file-bus.md`).** New stdlib-only `nexus_lite.filebus`: one JSON file per message under `<workspace>/bus/msg/<target>/` (ids `m<ms>-<writer>-<ctr>`, tmp file + atomic rename, no lock; blobs for bodies over 256 KiB), per-(target, consumer) cursor files with a high-water mark and a 300 s skew window (late arrivals are still delivered once; older ones are only reported by `bus read --audit`), session heartbeat files, a `VERSION` file (a newer major is refused, exit 2). Any directory is a bus: `NEXUS_BUS_DIR` or `nexus-lite bus --bus-dir DIR ...`, so a VM, a sandbox, Colab/Drive or loom shares it by sharing the folder and the file-mailbox relay is no longer needed. The public `mtm` API and `nexus-lite bus` commands keep their semantics: `seq` is now this index's local ingest counter; `bus_read` / `bus_wait` take `since_id` (file-native); `bus_ack` also takes a message id; new `bus read --audit`, `bus reindex`, `bus prune --sessions`, `bus where` (prints the resolved bus dir: `--bus-dir` > `$NEXUS_BUS_DIR` > `<workspace>/bus`); `bus send` and `bus wait` print `bus: <dir>` on stderr so a sender and a waiter that resolved different `.nexus` dirs are visible. Writers still create `.nexus/inbox/<id>.md` and `path` points at it for one more release. An existing `lite.db` bus is migrated into files by schema migration 5 (unacked messages, sessions and cursors; deterministic ids, so a retry rewrites the same files).
- **Wake-up layer:** a sender pings the target's waiters through a local Unix datagram socket (outside the bus dir; `$NEXUS_BUS_RUN_DIR`, `$XDG_RUNTIME_DIR/nexus-bus`), a session file may advertise a Unix socket or a loopback-only TCP port; `bus wait` and `bus_watch` block on it and rescan every `--poll-s` as the fallback (slower after 60 s idle). A lost signal costs latency, never a message.
- **`nexus-lite job start NAME --notify TARGET`:** the job supervisor sends one `job` bus message (summary `<name> <verdict> rc=<rc>`, `data` name/verdict/rc/run_dir/ts/supervisor/job_id) when the job reaches a terminal state, so a waiter needs only `bus wait`.
- `nexus-lite bus wait --target NAME [--timeout S]`: blocks until the target has an unacked message, prints it as `bus read` does and exits 0 (124 on timeout). Nothing is acked. Run it in the background to be woken when a message arrives, instead of polling.

## v0.3.2

### Fixed
- **PTY tests and errors on macOS.** The pty test harnesses keep the slave side open and keep reading while they wait for exit, as a shell and a terminal emulator do (XNU drops unread output when the last slave descriptor closes, and `tcsetattr(TCSADRAIN)` blocks until the master reads pending output). The long socket path test uses `control.SUN_PATH_MAX` (103 bytes, the macOS limit). `serve` and `attach` now print `AF_UNIX path too long` instead of `None` for a socket path that is too long.
- **Picker relist race:** after an attach returns, the picker waits up to 2 s for an ended session's socket to disappear, so the relisted table no longer shows a session that just exited.
- PTY golden fixtures no longer contain local paths or issue references.

### Changed
- **qradiomics demos for qradiomics v0.9.8+:** pyradiomics is optional (qradiomics uses its `rtools` engine by default); the Colab demo notebook and `nexus_lite.demos` work without it. `v022_primitives_colab.ipynb` is now `kernel_primitives_colab.ipynb`. `skills/nexus-colab` describes two tiers: in-notebook bootstrap and the optional remote tunnel.
- **PTY sessions need no `dtach` binary.** `pty.spawn()` now starts every session with the stdlib server `nexus_lite.ptyd` (`python -m nexus_lite.ptyd -r winch <sock> -- <cmd...>`), an independent implementation of the dtach 0.9 client interface: the 10-byte `<BB8s` packets (PUSH, ATTACH, DETACH, WINCH, REDRAW with the none/ctrl_l/winch methods), several clients at once, output only to attached clients, socket mode 0600 plus the owner execute bit while a client is attached, double-fork detach, the program as its own session and process-group leader, SIGCHLD reaping (no zombies), and socket removal on exit. Existing dtach clients (nexus-lite's own, nexus.code `dtach_ctl`, `dtach -a/-p`) work unchanged. The server writes `<sock>.pid`; its argv carries the socket path as an exact token. `NEXUS_LITE_DTACH=binary` opts back into an installed `dtach` binary. `colab.ensure_env()` / `ensure_colab()` no longer apt-install `dtach`; CI, the dev container and the notebooks no longer install it.
- `find_dtach_master_pid` / `kill_session` recognise `nexus_lite.ptyd` masters, `dtach` binary masters, and the previous `python -m nexus_lite.pty --serve` daemon, so sessions started before the upgrade can still be found and killed. The `--serve` fallback daemon is removed.

### Added
- **`nexus_lite.pty` is now a package and the complete, dependency-free PTY primitive (#44).** `pty.py` + `ptyd.py` became `nexus_lite/pty/`: `protocol` (dtach 0.9 `<BB8s` packets), `server` (holds the PTY, serves the socket), `client` (interactive `attach` and the programmatic `Connection`), `control` (`spawn` / `send` / `keys` / `read` / `wait` / `kill` / discovery), `screen`, `agents` (agent command normalization), `cli`. Every name `nexus_lite.pty` exported before is still importable from the package (`pty.spawn(...)` etc.), and `nexus_lite.ptyd` (module and `python -m nexus_lite.ptyd` command line) stays as a re-export shim for one release. Specification: `docs/specs/pty-package.md`.
- **Session server command line `python -m nexus_lite.pty serve|attach`**, dtach-compatible flags: `-A` attach-or-create (stale socket safe, under the socket lock: never two masters, also when several `-A` race), `-c` create-and-attach, `-N` foreground without forking (exit code = the program's, `128+N` on a signal, `127` when it cannot be executed), `-z` accepted as a no-op, `-r`, `-e`, `-E`. `spawn()` now starts `python -m nexus_lite.pty serve -r winch SOCK -- CMD`; the master's argv still carries the socket path as an exact token, and `find_dtach_master_pid` / `kill_session` recognise the new form besides `nexus_lite.ptyd`, `dtach` binary and the old `--serve` masters. A plain `serve` (and `-A`/`-c`) replaces a stale socket file instead of failing with "Address already in use", and never unlinks a path that is not a socket.
- **ATTACH alone triggers the winch redraw** when the session redraw method is `winch` (dtach 0.9 `-r winch`): no REDRAW packet is needed.
- **`nexus_lite.pty.screen`: a stdlib VT text-screen reader replaces `pyte`**, `nexus-lite` has no runtime dependencies any more. Character grid only (no colours or attributes): CR/LF/BS/TAB, CUP/CUU/CUD/CUF/CUB/CNL/CPL/CHA/HPA/VPA, ED/EL/ECH, ICH/DCH/IL/DL, DECSTBM + IND/RI/NEL/SU/SD, DECSC/DECRC, alternate screen (47/1047/1049), DECOM/DECAWM/IRM/LNM, wide/combining/zero-width characters; SGR, OSC, DCS/APC and unknown sequences are parsed and dropped. Own bounded scrollback of the rows scrolled off the top (`Screen.scrolled`, `Screen.pushed`); `ESC[3J` clears the scrollback only. Every control function is an overridable method with the pyte-compatible name (the documented extension point: cells are opaque to the movement operations, a subclass overrides `make_cell` / `blank_cell` / `cell_text` / `select_graphic_rendition` to track attributes). Golden tests render recorded raw output of claude, agy, codex, copilot, gemini, opencode and bash identically to pyte (tests/fixtures/pty); pyte stays only as a dev extra for generating and cross-checking those goldens.
- **`nexus-lite pty ls` and an interactive attach picker (#45).** `pty ls` prints NO / NAME / PROVIDER / AGE / ATTACHED / ALIVE (provider and age from a new `<sock>.meta` written by `spawn`; ATTACHED = a person is attached). `pty attach` without a name is a numbered picker that returns to the list after every detach; `pty attach <number|name>` matches a number, an exact name or a unique substring. Detach key `Ctrl-\` (dtach-compatible), `-e CHAR` / `$NEXUS_PTY_DETACH` to change it, `-E` to disable it; `--ro` watches without ever sending PUSH (`q` also detaches). Hint `[attached: NAME - Ctrl-\ to detach]` and `[detached: NAME]`, winsize + winch redraw on attach, local terminal restored. Works for dtach-binary sessions. New module `nexus_lite.pty.picker`; `pty.attach(name, ..., ro=, label=, redraw=)`.
- **Human input stamp:** the stdlib server writes the epoch time of every keystroke an attached interactive client sends to `<sock>.input` (atomic, mode 0600, removed with the socket and `.pid`); `pty.last_human_input(sock)` reads it. `control.send` / `keys` connections never ATTACH, so programmatic injection does not stamp. Output-capture sidecars mark themselves with `MSG_SIDECAR` (type 5, a nexus-lite extension that dtach ignores) and count neither as attached nor as human.
- `scripts/make_pty_goldens.py` (golden fixture generator) and `tests/test_pty_server_cli.py`, `tests/test_pty_screen.py`, `tests/test_pty_screen_golden.py`.
- `nexus-lite pty attach NAME [-e ^X | -E]` and `pty.attach(name)`: interactive raw-mode attach (detach with Ctrl-\\ by default; no suspend key, Ctrl-Z goes to the program). Also `python -m nexus_lite.ptyd -a SOCK`.
- `scripts/ptyd_stress.py`: bounded stress run (N sessions, attach/redraw/push/detach cycles, fd and RSS flatness, teardown checks).

## v0.3.0

### Added

- `nexus_lite.jobs` and `nexus-lite job start|status|wait|check|tail|stop|list`: detached jobs whose state lives on disk (new session and process group, stdin closed; run dir with pid, pgid, process start time, boot id, rc). Liveness answered once: a recorded rc is ground truth, a failed sentinel assertion turns rc 0 into FAIL, a pid counts only when its start time and boot id match (reused pids are GONE and never signalled), unmeasurable is UNKNOWN/AMBIGUOUS and never terminal; a valid resume sentinel is SKIP. `wait` prints one line with an exit code from the state; `check` gives a verdict without the raw log. Root: `--root`, `$NEXUS_LITE_JOBS_ROOT`, or `<workspace>/jobs`.
  Re-running a name moves the previous run to `<name>/prev/<stamp>/` (all kept unless `keep`/`--keep` is set); a name whose job is not terminal (AMBIGUOUS, UNKNOWN, RUNNING with another command) is refused unless `force`; `start` returns the verified state (UNKNOWN with a detail when no pid or rc appeared; CLI exit 3). Each run has a `run_id`; a run moved to `prev/` by a forced restart records its rc there, never over the new run; force on a verified running job stops it first; `keep` must be an integer >= 0.
- `delegate(..., completion_detail=False)` and the `run_swarm` spec key `completion_detail`: the TASK_COMPLETE /
  TASK_ESCALATE message carries the status only, never worker output or the escalation reason.
- Artifact primitives: path-free logical manifest (schema 2: `cas.logical_entry`/`put_logical_manifest`/`write_logical_manifest`/`logical_manifest`), machine-local location registry `nexus_lite.locations` (`record`/`record_many`/`by_sha256`/`by_artifact_id`/`forget`), and `cas.DERIVED_EXTENSIONS` + `exclude_ext=` on `manifest`/`add`/`diff`/`status`. See `docs/artifact-primitives.md`.
- `delegate(..., route_handoffs=False)` and the `run_swarm` spec key `route_handoffs`: opt-in routing of `[nexus] handoff <target> - <summary>` lines in task output via `bus_send(kind="handoff", sender=task_id)`. Invalid targets are skipped and logged to stderr, never raised. New `protocol.parse_handoffs`.
- `memory.mtm.bus_watch()`: generator/callback consumer over `bus_read(unacked=True, consumer=...)` + `bus_ack`; independent "watch" cursor, `timeout`, `ack=False` replay.
- PTY on macOS/POSIX: `find_dtach_master_pid` checks a `<sock>.pid` sidecar, then `/proc`, then a `ps -axo` parse (no `pgrep`); `kill()` SIGTERM->SIGKILLs the master on macOS too and removes the sidecar. When the `dtach` binary is absent (or `NEXUS_LITE_DTACH=python`) `spawn()` runs a stdlib fallback daemon (`python -m nexus_lite.pty --serve <sock> -- <cmd>`: `os.forkpty` + AF_UNIX + `select`, same `<BB8s` protocol, writes `<sock>.pid`, exits when the child exits or `<sock>` is unlinked). The `dtach` binary is now optional. New `pty.inject_or_send(name, text=None, *, bus_kind=None, summary=None, ...)` pushes raw text or a bus pointer and returns the settled screen tail.
- Bus multi-consumer cursors (schema v3): `bus_read(..., unacked=True, consumer=)` and `bus_ack(target, seq, consumer=)` keep independent cursors per (target, consumer), e.g. a PTY watcher vs a turn prompt builder; `consumer=None` is the old default cursor (existing rows migrate to it). `bus_prune` deletes a direct message only when every consumer of its target acked it.
- `run_swarm` dependency sub-waves: optional spec keys `id`/`task_id`, `depends_on`, `subwave`, `prompt_fn(results_so_far)` (lazy), `inject_bus_inbox` (default False; prepends unacked pointers, consumer `turn`), `bus_targets` (TASK_COMPLETE to each after the spec ends). Unknown dep or cycle raises `ValueError` before dispatch; specs without these keys behave as before.
- `nexus-lite pc ...` and `nexus-lite colab ...` (start/stop/status/exec/pc) are now available on the main `nexus-lite` CLI via lazy dispatch to `nexus_lite.colab.tunnel`; `nexus-lite-colab` keeps working. `nexus_lite.cli` still never imports `nexus_lite.colab` at import time.

## v0.2.2

### Added
- `nexus_lite.loom.install_loom` + CLI `nexus-lite loom install [--version V] [--dest PATH]`: explicit, opt-in install of the pinned released loom binary (`LOOM_VERSION`), sha256-verified against the release `checksums.txt`; never runs implicitly.
- Bus v1 (schema v2): integer monotonic `messages.seq` (returned by `bus_send`), `bus_cursors` + `bus_ack`, `bus_register`/`bus_unregister` over `sessions` (new `last_seen`; `ALL` reaches only live registered sessions, TTL `LIVE_TTL_S`; unacked direct messages re-emitted once on register), `bus_read(since_seq=, unacked=)`, `bus_prune` + CLI `bus ack|register|unregister|prune`, control-char/type validation (`protocol.validate_bus_field`). Single-instance scope; additive.
- `nexus_lite.phi.phi_gate_error`: minimal opt-in PHI gate. With `NEXUS_SENSITIVITY=phi`, `core.delegate` refuses non-local runners (allowed: `ollama` except `launch`, `sh/bash/zsh/dash`, python) and forces `fallback_cmd=None`; `run_multi_tier_swarm(phi=True)` now builds Tier-0 as `ollama run <model>` (default `llama3.2`) instead of opencode. Unset/other value = no change. Stateless: no store, no endpoint probe.
- `nexus_lite.provider_errors`: pure stdlib quota/auth classifier (`classify_provider_error` -> `rate_limit|quota|auth|None`, JSON error bodies, `is_quota_or_auth_failure`); `core` keeps private aliases. Marker lists merged with those of downstream consumers.
- `nexus_lite.guard`: env-driven delegation depth / leaf guard primitive (`leaf_guard_error`, `current_delegation_depth`, `max_delegation_depth`); honors `NEXUS_MAX_DELEGATION_DEPTH`, `NEXUS_DELEGATED_ROLE`, `NEXUS_ALLOW_NESTED_MININEXUS`. Downstream consumers import and extend it.

- `nexus_lite.artifacts`: one task-artifact layout contract (file-name constants, `artifacts_root`, `task_dir`, `export_env`, `task_dir_from_env`). `delegate` now also writes `result.md` (same bytes as `output.md`) and `meta.json` `{task_id, agent, status, rc, started, finished}`; workers get the per-task dir as `NEXUS_TASK_DIR`; the artifact root is an argument (default `<workspace>/artifacts`, no env override).

### Changed
- `core.delegate` uses the guard instead of a hardcoded depth 2; default env behaviour unchanged, an unparseable `NEXUS_DELEGATION_DEPTH` is now refused instead of treated as 0.

### Breaking Changes
- **Colab Tunnel Relocation**: Relocated `nexus_lite.bridge` out of the core kernel into a standalone Colab utility `nexus_lite.colab.tunnel` (`ColabTunnelClient`, `start_tunnel`, `stop_tunnel`, `get_tunnel_info`, `is_tunnel_alive`).
- Dropped the `bridge` subcommand from the main `nexus-lite` CLI; exposed the utility as its own console script `nexus-lite-colab` and `python -m nexus_lite.colab.tunnel`.
- Core kernel no longer imports or lazy-loads the network service daemon (`nexus_lite.colab.tunnel`), adhering to the Open-Core-Kernel Unix CLI architecture (§2: no daemon in core). Removed all compatibility shims under the old `bridge` name.
- Added: public `nexus_lite.pty.find_dtach_master_pid`, `PROVIDER_MANIFESTS`, `classify` (states `none|needs_input|working|idle`); `is_busy`/`is_idle` now derive from the manifests. `_find_dtach_pid` kept as an alias.
- Fixed: dtach master resolver no longer falls back to `matches[0]` when no/several candidates own children (ambiguous -> `None`).
- Added: public packet aliases `nexus_lite.pty.PKT`, `PUSH_MAX`, `packet`, `winch_packet` (private names kept) for downstream imports.

### Changed
- **Memory package**: the three memory tiers are now separate modules under `nexus_lite.memory`: `stm` (was `nexus_lite.stm` plus `core.stm_*`), `mtm` (file/SQLite bus and inbox pointer delivery: `bus_send`, `bus_read`), `ltm` (markdown wiki plus FTS5: `wiki_write/read/search/list`). Workspace path and SQLite helpers moved to `nexus_lite._db` (still re-exported by `core`). No function renamed; CLI subcommands, SQLite tables, `.nexus/` layout, `stm/1` files and pointer lines are unchanged. Top-level `nexus_lite.bus_send` etc. keep working without warning.
- `import nexus_lite` is now lazy for `core`: only `pty`, `roles`, `protocol` load eagerly, so `import nexus_lite.memory.<tier>` pulls in no other tier, core, colab, demos or viz.

### Kernel/demo split
- **Breaking: CLI.** `demo`, `multi-tier`, `interact`, `cooperate` and `dashboard` left `nexus-lite`; they are now `nexus-lite-demo <subcommand>` (`python -m nexus_lite.demos`). `nexus-lite --help` lists kernel subcommands only.
- **Breaking: module paths.** `nexus_lite.demos` is now a package: `demos.scenarios` (old `demos.py`), `demos.orchestration` (`run_multi_tier_swarm`, `run_agent_interaction`, `run_cooperative_problem_solver`, formerly in `core`), `demos.viz`, `demos.loom_multi_agent|loom_multi_task|loom_radiomics_tasks`. The old `nexus_lite.viz` / `nexus_lite.loom_*` paths remain as deprecated shim modules. Colab helpers (`colab_sync_*`, `sync_dotdir_to_drive`, `ColabInitResult`, `detect_env`, `ensure_colab`, `ensure_env`) moved to `nexus_lite.colab.env` (also exported from `nexus_lite.colab`).
- **Breaking:** `get_db` and `get_db_path` are no longer in `nexus_lite.__all__` (import from `nexus_lite._db`). The `loom.py` adapter stays in the core namespace.
- `run_swarm(live_viz=...)` is ignored with a `DeprecationWarning` (the core renders no dashboards). The unused `max_turns` key in the multi-tier Tier-0 spec was removed.
- `nexus_lite.__version__` now comes from the installed package metadata (pyproject is the single source; falls back to an adjacent `pyproject.toml`).
- The core (`core`, `cli`, `memory`, ...) never imports `nexus_lite.demos` or `nexus_lite.colab`; a test enforces it. `ensure_opencode` stays in `core` because `run_swarm` uses it.

### Deprecated
- `NEXUS_ARTIFACT_DIR` (per-task dir env): still exported with the same value as `NEXUS_TASK_DIR` and accepted on read (canonical wins); removed after one release.
- Old names `core.{run_multi_tier_swarm,run_agent_interaction,run_cooperative_problem_solver,colab_sync_to_drive,colab_sync_from_drive,sync_dotdir_to_drive,ColabInitResult,detect_env,ensure_colab,ensure_env,...}` and top-level `nexus_lite.{run_*_demo*,dashboard,render_dashboard_html,watch,ensure_env,ensure_colab,detect_env,sync_dotdir_to_drive,get_db,get_db_path,...}`: resolved lazily with a `DeprecationWarning`; removed after one release.
- `nexus_lite.stm` (import path), and `nexus_lite.core.{bus_send,bus_read,wiki_write,wiki_read,wiki_search,wiki_list,stm_write,stm_read,stm_list,stm_rebuild_index,stm_search,stm_pack}`: still work via thin aliases but emit `DeprecationWarning`; removed after one release. Use `nexus_lite.memory.*`.
