# Changelog

Release notes for nexus-lite. Each GitHub Release uses its version section.

## v0.3.0

### Added
- `skills/nexus-agent-team/` section 8: handoffs (the `[nexus] handoff caller - <summary>` return convention on the existing `parse_handoffs` grammar, `handoff/<task_id>.md` status enum, clean-exit-only, gates before handoff, lead-configured limits. Docs only, no code change.
- Jobs J2: `nexus-lite job digest` (check for several jobs; check now carries the assertion and the most frequent error signature), `job load` (our runnable processes, not counting itself, against our CPU quota, which must be given: `--quota` or `$NEXUS_LITE_CPU_QUOTA`), `job wait-for` (poll an external state until terminal; one line with the state capped at 200 characters; interval and timeout have no defaults; each poll is bounded by the remaining time), `nexus_lite.ledger` with `job ledger step|begin|mark|commit` (one `#nexus.ledger/2` row per step event, skip only on a sentinel that passes its assertion now, atomic commit), `job scaffold` (a Python driver with preflight, ledger, resume and a quota gate; an existing driver is kept unless `--force`); step logs are appended per execution under a header, and the skill `skills/nexus-detached-jobs/`.
- `protocol.EdgeKind`, `normalize_edge`, `normalize_spawn`, `NON_LINK_KINDS`: agent links for orchestration, a general agent-to-agent relation primitive. `normalize_edge(messages row)` and `normalize_spawn(tasks row)` project to exactly `{from, to, kind, ts}` (kinds dm, handoff, broadcast, task, receipt, spawn) or None when the row is not a link; no body, summary or path is ever emitted. Consumers: Office lines, the research viewer, handoff lineage.
- `skills/nexus-agent-team/`: how to run several agents and a human lead as one team over the bus (roles, message ids and pointers, draining with cursors, `bus_watch` consumers, a file-mailbox relay for agents without database access, approvals from the lead); `examples/agent_team_bus.py` runs it with scripted agents.
- `nexus_lite.jobs` and `nexus-lite job start|status|wait|check|tail|stop|list`: detached jobs whose state lives on disk (new session and process group, stdin closed; run dir with pid, pgid, process start time, boot id, rc). Liveness answered once: a recorded rc is ground truth, a failed sentinel assertion turns rc 0 into FAIL, a pid counts only when its start time and boot id match (reused pids are GONE and never signalled), unmeasurable is UNKNOWN/AMBIGUOUS and never terminal; a valid resume sentinel is SKIP. `wait` prints one line with an exit code from the state; `check` gives a verdict without the raw log. Root: `--root`, `$NEXUS_LITE_JOBS_ROOT`, or `<workspace>/jobs`.
  Re-running a name moves the previous run to `<name>/prev/<stamp>/` (all kept unless `keep`/`--keep` is set); a name whose job is not terminal (AMBIGUOUS, UNKNOWN, RUNNING with another command) is refused unless `force`; `start` returns the verified state (UNKNOWN with a detail when no pid or rc appeared; CLI exit 3). Each run has a `run_id`; a run moved to `prev/` by a forced restart records its rc there, never over the new run; force on a verified running job stops it first; `keep` must be an integer >= 0.
- `delegate(..., completion_detail=False)` and the `run_swarm` spec key `completion_detail`: the TASK_COMPLETE /
  TASK_ESCALATE message carries the status only, never worker output or the escalation reason.
- Artifact primitives: path-free logical manifest (schema 2: `cas.logical_entry`/`put_logical_manifest`/`write_logical_manifest`/`logical_manifest`), machine-local location registry `nexus_lite.locations` (`record`/`record_many`/`by_sha256`/`by_artifact_id`/`forget`), and `cas.DERIVED_EXTENSIONS` + `exclude_ext=` on `manifest`/`add`/`diff`/`status`. See `docs/artifact-primitives.md`.
- `delegate(..., route_handoffs=False)` and the `run_swarm` spec key `route_handoffs`: opt-in routing of `[nexus] handoff <target> - <summary>` lines in task output via `bus_send(kind="handoff", sender=task_id)`. Invalid targets are skipped and logged to stderr, never raised. New `protocol.parse_handoffs`.
- `memory.mtm.bus_watch()`: generator/callback consumer over `bus_read(unacked=True, consumer=...)` + `bus_ack`; independent "watch" cursor, `timeout`, `ack=False` replay.
- PTY on macOS/POSIX: `find_dtach_master_pid` checks a `<sock>.pid` sidecar, then `/proc`, then a `ps -axo` parse (no `pgrep`); `kill()` SIGTERM->SIGKILLs the master on macOS too and removes the sidecar. When the `dtach` binary is absent (or `NEXUS_LITE_DTACH=python`) `spawn()` runs a stdlib fallback daemon (`python -m nexus_lite.pty --serve <sock> -- <cmd>`: `os.forkpty` + AF_UNIX + `select`, same `<BB8s` protocol, writes `<sock>.pid`, exits when the child exits or `<sock>` is unlinked). The `dtach` binary is now optional. New `pty.inject_or_send(name, text=None, *, bus_kind=None, summary=None, ...)` pushes raw text or a bus pointer and returns the settled screen tail.
- Bus multi-consumer cursors (schema v3): `bus_read(..., unacked=True, consumer=)` and `bus_ack(target, seq, consumer=)` keep independent cursors per (target, consumer), e.g. a PTY watcher vs a turn prompt builder; `consumer=None` is the old default cursor (existing rows migrate to it). `bus_prune` deletes a direct message only when every consumer of its target acked it.
- `run_swarm` dependency sub-waves: optional spec keys `id`/`task_id`, `depends_on`, `subwave`, `prompt_fn(results_so_far)` (lazy), `inject_bus_inbox` (default False; prepends unacked pointers, consumer `turn`), `bus_targets` (TASK_COMPLETE to each after the spec ends). Unknown dep or cycle raises `ValueError` before dispatch; specs without these keys behave as before.
- `nexus-lite pc ...` and `nexus-lite colab ...` (start/stop/status/exec/pc) are now available on the main `nexus-lite` CLI via lazy dispatch to `nexus_lite.colab.tunnel`; `nexus-lite-colab` keeps working. `nexus_lite.cli` still never imports `nexus_lite.colab` at import time.
- `notebooks/v022_primitives_colab.ipynb` (generated by `examples/make_notebooks.py`): Colab walkthrough of memory tiers (`nexus_lite.memory.{stm,mtm,ltm}`), Bus v1 (`seq`, `bus_ack`/`bus_cursors`, `bus_register` offline redelivery, `bus_prune`), the `NEXUS_SENSITIVITY=phi` gate with `stm/1` summary redaction, and zero-preinstall remote compute (`pack_self_contained_script` / `run_on_colab`). All 7 Colab notebooks are linked in the top badge table of `README.md`; hygiene tests in `tests/test_notebooks.py`.

### Removed
- Non-Colab remote compute: `run_on_turing`, `turing_job_status`, the `hpc`/`turing` targets of `compute_run` and `nexus-lite compute`, and the SLURM/SSH-cluster options. `colab` and `local` targets remain; `compute_run` now defaults to `colab`.

### Fixed
- Review fixes. PHI: under `NEXUS_SENSITIVITY=phi` the `TASK_COMPLETE`/`TASK_ESCALATE`, `bus_targets`, pipeline `HANDOFF` and routed handoff messages carry only task id + status (never worker output/reason); `mtm.bus_send` redacts non-pointer `task`/`handoff` text; handoff target `ALL` is always rejected. Perms: workspace/inbox/artifacts/pcs dirs 0700 and inbox/artifact/pc-meta files 0600; the tunnel token dir is verified (real dir, own uid, 0700) and token files are opened `O_NOFOLLOW`; `--token` (colab start/exec/pc bind) is deprecated with a warning in favour of `--token-file` / `NEXUS_LITE_TOKEN`. Cursors: the `turn` cursor is acked only after the spec was dispatched; `bus_prune` keeps `ALL` messages a live registered session without a cursor has not read; `bus_register` re-sends everything above the lowest cursor in use; a timed-out sub-wave task is marked `timeout` and its dependents are skipped (`status: skipped`); agent commands are parsed with `shlex` like the PHI gate.
- `loom_multi_agent.secrets_env()` now falls back to `os.environ` when `google.colab.userdata` is importable but returns nothing or raises; tests resolve repo paths from `__file__` so `pytest` passes from any working directory (e.g. Colab `/content`).

## v0.2.2

### Added
- `nexus_lite.loom.install_loom` + CLI `nexus-lite loom install [--version V] [--dest PATH]`: explicit, opt-in install of the pinned released loom binary (`LOOM_VERSION`), sha256-verified against the release `checksums.txt`; never runs implicitly.
- Bus v1 (schema v2): integer monotonic `messages.seq` (returned by `bus_send`), `bus_cursors` + `bus_ack`, `bus_register`/`bus_unregister` over `sessions` (new `last_seen`; `ALL` reaches only live registered sessions, TTL `LIVE_TTL_S`; unacked direct messages re-emitted once on register), `bus_read(since_seq=, unacked=)`, `bus_prune` + CLI `bus ack|register|unregister|prune`, control-char/type validation (`protocol.validate_bus_field`). Single-instance scope; additive.
- `nexus_lite.phi.phi_gate_error`: minimal opt-in PHI gate. With `NEXUS_SENSITIVITY=phi`, `core.delegate` refuses non-local runners (allowed: `ollama` except `launch`, `sh/bash/zsh/dash`, python) and forces `fallback_cmd=None`; `run_multi_tier_swarm(phi=True)` now builds Tier-0 as `ollama run <model>` (default `llama3.2`) instead of opencode. Unset/other value = no change. Stateless: no store, no endpoint probe.
- `nexus_lite.provider_errors`: pure stdlib quota/auth classifier (`classify_provider_error` -> `rate_limit|quota|auth|None`, JSON error bodies, `is_quota_or_auth_failure`); `core` keeps private aliases. Marker lists merged with those of downstream consumers.
- `nexus_lite.guard`: env-driven delegation depth / leaf guard primitive (`leaf_guard_error`, `current_delegation_depth`, `max_delegation_depth`); honors `NEXUS_MAX_DELEGATION_DEPTH`, `NEXUS_DELEGATED_ROLE`, `NEXUS_ALLOW_NESTED_MININEXUS`. Downstream consumers import and extend it.

- `nexus_lite.artifacts`: one task-artifact layout contract (file-name constants, `artifacts_root`, `task_dir`, `export_env`, `task_dir_from_env`). `delegate` now also writes `result.md` (same bytes as `output.md`) and `meta.json` `{task_id, agent, status, rc, started, finished}`; workers get the per-task dir as `NEXUS_TASK_DIR`; the artifact root is an argument (default `<workspace>/artifacts`, no env override).

### Changed
- `core.delegate` uses the guard instead of a hardcoded depth 2; default env behaviour unchanged, an unparseable `NEXUS_DELEGATION_DEPTH` is now refused instead of treated as 0.

### Breaking Changes
- **Colab Tunnel Relocation**: Relocated `nexus_lite.bridge` out of the core kernel into a standalone Colab utility `nexus_lite.colab.tunnel` (`ColabTunnelClient`, `start_tunnel`, `stop_tunnel`, `get_tunnel_info`, `is_tunnel_alive`).
- Dropped the `bridge` subcommand from the main `nexus-lite` CLI; exposed the utility as its own console script `nexus-lite-colab` and `python -m nexus_lite.colab.tunnel`.
- Core kernel no longer imports or lazy-loads the network service daemon (`nexus_lite.colab.tunnel`), adhering to the Open-Core-Kernel Unix CLI architecture (§2: no daemon in core). Removed all compatibility shims under the old `bridge` name.
- Added: public `nexus_lite.pty.find_dtach_master_pid`, `PROVIDER_MANIFESTS`, `classify` (states `none|needs_input|working|idle`); `is_busy`/`is_idle` now derive from the manifests. `_find_dtach_pid` kept as an alias.
- Fixed: dtach master resolver no longer falls back to `matches[0]` when no/several candidates own children (ambiguous -> `None`).
- Added: public packet aliases `nexus_lite.pty.PKT`, `PUSH_MAX`, `packet`, `winch_packet` (private names kept) for downstream imports.

### Changed
- **Memory package**: the three memory tiers are now separate modules under `nexus_lite.memory`: `stm` (was `nexus_lite.stm` plus `core.stm_*`), `mtm` (file/SQLite bus and inbox pointer delivery: `bus_send`, `bus_read`), `ltm` (markdown wiki plus FTS5: `wiki_write/read/search/list`). Workspace path and SQLite helpers moved to `nexus_lite._db` (still re-exported by `core`). No function renamed; CLI subcommands, SQLite tables, `.nexus/` layout, `stm/1` files and pointer lines are unchanged. Top-level `nexus_lite.bus_send` etc. keep working without warning.
- `import nexus_lite` is now lazy for `core`: only `pty`, `roles`, `protocol` load eagerly, so `import nexus_lite.memory.<tier>` pulls in no other tier, core, colab, demos or viz.

### Kernel/demo split
- **Breaking: CLI.** `demo`, `multi-tier`, `interact`, `cooperate` and `dashboard` left `nexus-lite`; they are now `nexus-lite-demo <subcommand>` (`python -m nexus_lite.demos`). `nexus-lite --help` lists kernel subcommands only.
- **Breaking: module paths.** `nexus_lite.demos` is now a package: `demos.scenarios` (old `demos.py`), `demos.orchestration` (`run_multi_tier_swarm`, `run_agent_interaction`, `run_cooperative_problem_solver`, formerly in `core`), `demos.viz`, `demos.loom_multi_agent|loom_multi_task|loom_radiomics_tasks`. The old `nexus_lite.viz` / `nexus_lite.loom_*` paths remain as deprecated shim modules. Colab helpers (`colab_sync_*`, `sync_dotdir_to_drive`, `ColabInitResult`, `detect_env`, `ensure_colab`, `ensure_env`) moved to `nexus_lite.colab.env` (also exported from `nexus_lite.colab`).
- **Breaking:** `get_db` and `get_db_path` are no longer in `nexus_lite.__all__` (import from `nexus_lite._db`). The `loom.py` adapter stays in the core namespace.
- `run_swarm(live_viz=...)` is ignored with a `DeprecationWarning` (the core renders no dashboards). The unused `max_turns` key in the multi-tier Tier-0 spec was removed.
- `nexus_lite.__version__` now comes from the installed package metadata (pyproject is the single source; falls back to an adjacent `pyproject.toml`).
- The core (`core`, `cli`, `memory`, ...) never imports `nexus_lite.demos` or `nexus_lite.colab`; a test enforces it. `ensure_opencode` stays in `core` because `run_swarm` uses it.

### Deprecated
- `NEXUS_ARTIFACT_DIR` (per-task dir env): still exported with the same value as `NEXUS_TASK_DIR` and accepted on read (canonical wins); removed after one release.
- Old names `core.{run_multi_tier_swarm,run_agent_interaction,run_cooperative_problem_solver,colab_sync_to_drive,colab_sync_from_drive,sync_dotdir_to_drive,ColabInitResult,detect_env,ensure_colab,ensure_env,...}` and top-level `nexus_lite.{run_*_demo*,dashboard,render_dashboard_html,watch,ensure_env,ensure_colab,detect_env,sync_dotdir_to_drive,get_db,get_db_path,...}`: resolved lazily with a `DeprecationWarning`; removed after one release.
- `nexus_lite.stm` (import path), and `nexus_lite.core.{bus_send,bus_read,wiki_write,wiki_read,wiki_search,wiki_list,stm_write,stm_read,stm_list,stm_rebuild_index,stm_search,stm_pack}`: still work via thin aliases but emit `DeprecationWarning`; removed after one release. Use `nexus_lite.memory.*`.

## v0.2.1
- loom adapter: `crash` status for signal exits (rc<0); `bad_output` status when rc=0 but stdout is not JSON (was ok with `result=None`).
- loom multi-agent example: now a real build (orchestrator splits a spec, workers write files with loom `write_file` into a kept sandbox, reviewer plus harness run pytest, up to 3 review rounds (at most 2 rework rounds), single-agent baseline, per-agent table). Mock path is offline and deterministic (harness writes scripted payloads).
- `agent()` no longer raises on timeout/OSError; no longer passes `--max-total-tokens` (rejected by loom v0.1.1; loom v0.2.x accepts it, still not passed).
- loom multi-agent example, reworked: four-module spec with subtle traps (caseless identifiers, half-open intervals, TTL boundary, ties-to-even rounding); hidden acceptance tests outside the sandbox (never in prompts; workers see only failing test names and failure kinds); single-agent baseline scored on the same hidden tests (optional separate self-repair rounds).
- A failed orchestrator/worker/reviewer now fails the run (exit 1, `RESULT: FAIL (...)` line) instead of reporting PASS. Per-agent stderr summaries with key redaction (`sk-ant-`, `AIza`, `*_API_KEY=`, bearer tokens, exact secret values); new `auth` status.
- Bounded retries (`--retries`, none for auth errors) and provider fallback; per-agent failure injection (`--inject-bad-key ROLE`, `--inject-timeout ROLE=SEC`) with deterministic mock equivalents (`mock,mock2` providers).
- Default loom is release `v0.2.1` (`LOOM_TAG`, override via env; checksum-verified `loom-linux-amd64`, source-build fallback). v0.2.1 adds `usage` in `--json`, recoverable policy-violation tool errors and an 8192 default output cap; a flag named only `--key` is not yet redacted in trace argv.
- Observability and CLI: loom version (or `n/a (reason)`), tokens or `n/a (reason)`, `--runs N`, `--json-out`, `--log-file`. `examples/loom_multi_agent.py` prefers the checkout over an older installed nexus-lite and prints an install hint if the module is missing.
- Tests: failure injection (bad/missing key, crash, timeout, bad output, provider fallback, checksum mismatch, key hygiene); loom tests added to GitLab and GitHub CI.
